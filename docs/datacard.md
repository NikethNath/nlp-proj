# Data card: Malayalam and Tamil orthography corpus

A controlled corpus for measuring how language models degrade when Malayalam
and Tamil are written in Latin script, and whether that degradation comes from
the change of script or from inconsistent spelling. It has two arms: a
controlled arm built from FLORES-200, where only orthography varies, and an
ecological arm of real romanized YouTube comments from DravidianCodeMix.

Figures below come from `docs/corpus_stats.json`, regenerated by
`python -m latscript.corpus_stats`.

## FLORES arm

Files: `flores_{ml,ta}_{dev,devtest}.jsonl`, 997 dev and 1,012 devtest
sentences per language, one JSON object per line.

| Field | Content |
|---|---|
| `id`, `idx`, `lang`, `split` | `flores-ml-devtest-0042`; `idx` is the FLORES line number, shared across languages |
| `english` | FLORES English reference |
| `l1_native` | L1: native script, as published |
| `l2_canonical` | L2: IndicXlit romanization, beam top-1, one deterministic form per word |
| `l2_lexical` | Alternative L2: most common human spelling in Dakshina, else Aksharantar, else a rule-based romanizer |
| `l3_writers` | L3: five simulated writers (list of 5 strings) |
| `human_coverage` | Share of native words with a human-attested spelling in Dakshina |
| `lexical_coverage` | The same share, counting Aksharantar too |

### How the levels are built

**L2, `l2_canonical`.** Each native-script word goes through IndicXlit
(indic→en, beam 4, no dictionary rescoring).

**L2, `l2_lexical`.** Uses the most frequent spelling among Dakshina
annotators. Aksharantar covers words Dakshina lacks, and a deterministic rule
romanizer (`translit/rules.py`) covers the rest. The rule romanizer handles
Malayalam's word-final half-u, nasal-cluster voicing, Tamil intervocalic
voicing and the റ്റ/ന്റ/ற்ற/ன்ற conjuncts. Each rule was checked against Dakshina
spellings.

**L3.** Human spelling variation is learned from Dakshina and replayed by five
fixed simulated writers:

1. A unit-level noise model learns how annotators deviate from the rule
   romanization (for example `aa`→`a`, final `u`→∅, Tamil `dh`→`th`). It is
   conditioned on word-final position.
2. Each writer draws a set of habits once, and only adopts habits that at least
   10% of annotators share.
3. If a word has at least 3 human attestations, the writer samples one of the
   real spellings, weighted by `count × exp(−0.5 × edit distance to the
   writer's habitual draft)`.
4. Other words get the writer's habitual draft. The most plausible of 4 draws
   under a character-trigram model of human spellings is kept.

Each writer spells a given word the same way everywhere, and writer *i* is the
same simulated person in every file.

### Statistics

| | Malayalam | Tamil |
|---|---|---|
| Sentences (dev + devtest) | 2,009 | 2,009 |
| Native word tokens | 28,801 | 32,173 |
| Words with a human-attested spelling | 67.8% | 77.3% |
| … counting Aksharantar | 86.8% | 93.7% |
| L3 word differs from `l2_lexical` | 37.9% | 38.7% |
| L3 word differs from `l2_canonical` | 51.3% | 50.5% |
| Two L3 writers spell a word differently | 42.8% | 42.7% |
| Two Dakshina annotators spell a word differently (words with ≥3 attestations) | 52.3% | 57.9% |
| L3 tokens flagged implausible by the trigram check | 1.1% | 1.3% |
| IndicXlit output is a human-attested spelling | 89.3% | 90.5% |
| IndicXlit output is the *most common* human spelling | 63.0% | 61.6% |

Real people disagree a lot: the most common spelling of a word matches a given
annotator's spelling only 69.5% of the time in Malayalam and 64.6% in Tamil.

## DravidianCodeMix arm

Files: `dcm_{ml,ta}_{train,dev,test}.jsonl`.

| Field | Content |
|---|---|
| `text` | The comment as posted |
| `label`, `label_name` | 0 `not_offensive`, 1 `offensive_untargeted`, 2 `offensive_targeted_individual`, 3 `offensive_targeted_group`, 4 `offensive_targeted_other`, 5 `not_in_language` |
| `offensive`, `in_language` | Labels 1-4; label ≠ 5 |
| `script`, `latin_ratio` | `latin` (≥90% of letters Latin), `native` (≤10%), `mixed`, `none` |
| `label_conflict`, `copies` | Duplicate comments collapsed into one row: whether their labels disagreed, and how many copies existed |
| `l1_backtranslit` | IndicXlit en→native back-transliteration, for Latin and mixed comments in dev and test; otherwise null |

**Sources and splits.**
- Tamil: `IsaacRodgz/DravidianCodeMix-Dataset`, whose train/dev/test splits all
  have labels.
- Malayalam: `community-datasets/offenseval_dravidian`, which has no labelled
  test set. Its validation split serves as test, and a stratified 10% of train
  becomes dev.

**Cleaning.**
- Duplicate comments within a split are collapsed; conflicting labels resolve
  to the majority, with ties going to the lower label id.
- Any comment present in an evaluation split is removed from the splits used
  for training. This matters for Malayalam: 944 of the 1,999 original
  validation comments also occurred in train, and Malayalam train shrinks from
  16,010 to 9,688 comments.

| | ml train | ml dev | ml test | ta train | ta dev | ta test |
|---|---|---|---|---|---|---|
| Comments | 9,688 | 1,077 | 1,921 | 34,756 | 4,369 | 4,382 |
| Latin script, in language | 5,396 | 602 | 1,023 | 26,727 | 3,391 | 3,418 |
| … of which offensive | 242 | 27 | 32 | 6,893 | 873 | 869 |
| Native-script comments | 2,363 | 269 | 500 | 5,545 | 681 | 669 |

## Human-written subset (in collection)

`collection/manifest.json` fixes 248 FLORES devtest sentences per language,
the same ones in both. Native speakers type them in Latin script via Google
Forms (`collection/README.md`). Every respondent types 8 shared anchor
sentences plus one set of 12. Responses will be released with pseudonymous
respondent codes once collected.

## Known limitations

- **L3 is simulated and somewhat conservative.** Simulated writers disagree on
  about 80% as many words as real annotators do, so degradation measured on L3
  is a mild lower bound. The human subset exists to check this.
- **The two L2s differ.** IndicXlit matches the most common human spelling only
  about 62% of the time. An L2→L3 difference measured against `l2_canonical`
  therefore includes a shift in convention as well as spelling variance;
  `l2_lexical` shares its source with L3 and isolates the variance.
- **Dakshina annotation errors.** Some Dakshina rows are misaligned by one row
  (ஹாரி romanized as "potter"). Pairs with normalized edit distance above 0.6
  from the rule romanization are dropped: 1.8% of Malayalam and 5.8% of Tamil
  lexicon attestations.
- **Malayalam offensive labels are sparse.** The Malayalam Latin-script test set
  has 32 offensive comments, too few for a stable offensive-class F1. Report
  per-class results with bootstrap intervals, or lean on Tamil for
  classification.
- **Few label disagreements.** Duplicate comments almost never carry different
  labels (14 conflicts in total), so they cannot supply a high-agreement
  subset.
- **Back-transliteration also nativizes English and Hindi.** Loanwords come out
  the way native-script typists often write them; whole non-target-language
  comments come out as noise (mostly labelled `not_in_language`).
